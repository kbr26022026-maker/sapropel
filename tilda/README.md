# Эко Органика для Tilda

Это не экспорт готового сайта в Tilda и не набор файлов, которые можно вставить в Tilda "как есть".

В папке лежат исходники секций в формате `HTML / CSS / JS` и локальные preview-страницы для проверки верстки. В Tilda это собирается вручную через `T123`, глобальные вставки сайта и замену локальных путей на реальные URL из Tilda/CDN.

Если просто вставить содержимое `background.css` или любого `*.css` файла в блок без тега `<style>`, Tilda покажет CSS как обычный текст. Именно это и происходит в вашем текущем сценарии.

Готовые собранные T123-сниппеты для всех вставляемых блоков лежат в папке `t123-snippets/`. Их можно вставлять в `T123` целиком, без ручной склейки `HTML + CSS + JS`.

## Что здесь реально готово

- Готова верстка секций и их стили.
- Готовы небольшие JS-сценарии для меню, reveal-анимаций, модалки документов и демо-формы.
- Есть локальный preview для проверки внешнего вида вне Tilda.

## Что здесь не готово "из коробки"

- Нет автоматического импорта в Tilda.
- Локальные пути вида `documents/...`, `08-contact/cta-bg.webp`, `../Badge_ozon.png` в Tilda работать не будут, пока вы не загрузите файлы в Tilda и не подставите новые URL.
- Форма в `08-contact` сейчас демонстрационная, без реальной отправки.
- `preview.html`, `preview-articles.html`, `preview-article.html` нужны только для локальной проверки и в Tilda не используются.

## Минимальная рабочая схема для Tilda

### 1. Сначала проверьте локальный preview

```bash
cd /Users/nikitasentyurin/VScode/sapropel/tilda
python3 -m http.server 5580
```

Откройте:

- `http://localhost:5580/preview.html`
- `http://localhost:5580/preview-articles.html`
- `http://localhost:5580/preview-article.html`

Если в preview все выглядит правильно, проблема уже не в верстке, а в способе вставки в Tilda.

### 2. Подключите глобальные зависимости сайта

Делается один раз на весь сайт.

1. В Tilda откройте `Настройки сайта -> Еще -> HTML-код для вставки внутрь HEAD`.
2. Вставьте содержимое файла `_global/head.html` целиком.
3. В это же поле `HTML-код для вставки внутрь HEAD` сразу под содержимым `_global/head.html` вставьте содержимое `_global/global.head.html`.

Важно:

- `_global/head.html` уже содержит `<style>...</style>`, туда не нужно ничего добавлять вручную.
- `_global/global.head.html` уже содержит обертку `<script>...</script>`, его можно вставлять в HEAD как есть.
- Если используете `_global/global.js`, его нужно обернуть в `<script>...</script>` вручную.
- Для этого проекта вставка скрипта в `HEAD` допустима: он сам ждет загрузки DOM и только потом инициализирует reveal-анимации.
- Поле `Пользовательские CSS-стили` можно не использовать: все нужные базовые стили уже находятся в `_global/head.html`.
- Без этих двух вставок секции будут частично ломаться: пропадут переменные темы, reveal-анимации и базовые стили.

### 3. Собирайте страницу только через T123

Для каждой секции создавайте отдельный блок `T123`.

Правильная схема вставки в `T123`:

```html
<style>
   /* вставить сюда содержимое section.css */
</style>

<!-- вставить сюда содержимое section.html -->

<script>
   /* вставить сюда содержимое section.js, если файл существует */
</script>
```

Правила:

- Не вставляйте `*.css` как обычный текст. Только внутрь `<style>`.
- Не вставляйте `*.js` как обычный текст. Только внутрь `<script>`.
- Если у секции нет `*.js`, блок `<script>` не нужен.
- Для каждого блока T123 в настройках желательно обнулить верхний и нижний отступ, чтобы не получить лишние зазоры от Tilda.
- Один T123 = одна секция. Не склеивайте сразу несколько крупных секций в один блок, иначе будет тяжело поддерживать и отлаживать.

## Обязательная ручная адаптация перед вставкой в Tilda

Это ключевая часть. Без нее проект вставится только частично.

### Ассеты и документы

В локальном preview используются относительные пути. В Tilda их не существует.

Нужно заранее загрузить файлы в Tilda или во внешний CDN и заменить ссылки в HTML.

Что заменить обязательно:

| Файл | Что сломается в Tilda | Что сделать |
|---|---|---|
| `08-contact/contact.html` | `08-contact/cta-bg.webp` не найдется | Загрузить картинку и заменить `src` на абсолютный URL |
| `09-footer/footer.html` | `../Badge_ozon.png` не найдется | Загрузить бейдж и заменить `src` |
| `07-resources/resources.html` | ссылки `documents/*.pdf` не найдутся | Загрузить PDF и заменить `href` и `data-preview` |
| `09-footer/footer.html` | `documents/privacy-policy.html` не существует в Tilda | Создать отдельную страницу в Tilda и заменить ссылку на ее URL |

Практический порядок:

1. Загрузите все PDF, картинки и дополнительные файлы в файловое хранилище Tilda.
2. Получите итоговые URL файлов.
3. Перед вставкой блока замените локальные пути в HTML на абсолютные URL.

### Формы

`08-contact/contact.js` сейчас только имитирует успешную отправку.

Реально рабочие варианты в Tilda такие:

1. Использовать штатный блок формы Tilda и стилизовать его отдельно.
2. Оставить текущую верстку и вручную подключить отправку в ваш endpoint/webhook.

Если нужен быстрый рабочий результат, лучше брать встроенную форму Tilda, а не полагаться на текущий демо-скрипт.

### Внутренние ссылки и URL страниц

В исходниках есть ссылки вроде `/`, `/articles/`, `/#contact`.

Перед публикацией проверьте, что:

- главная страница сайта в Tilda действительно открывается по `/`;
- страница блога действительно будет `/articles/`;
- секции на главной сохраняют нужные `id` для якорей.

Если структура URL в Tilda другая, ссылки нужно обновить вручную.

## Почему у вас сейчас CSS выводится текстом

Самая вероятная причина одна из этих:

1. В T123 был вставлен сам файл `background.css` без обертки `<style>`.
2. CSS был вставлен не в T123, а в другой тип блока, который не интерпретирует код как HTML.
3. В блок попал только CSS, но не HTML соответствующей секции.

Для фона правильный блок должен выглядеть так:

```html
<style>
   /* содержимое _background/background.css */
</style>

<!-- содержимое _background/background.html -->
```

Если после этого на странице по-прежнему виден CSS как текст, значит используется не тот блок Tilda или код был вставлен в визуальный редактор, а не в HTML-блок `T123`.

## Что точно проверять после вставки каждой секции

После каждого T123 проверяйте страницу сразу, а не после сборки всей главной.

Короткий чеклист:

1. CSS не отображается как текст.
2. Секция видна и выглядит как в локальном preview.
3. В консоли браузера нет ошибок по отсутствующим файлам.
4. Все изображения открываются по реальным URL.
5. Если у секции есть JS, он реально выполнился.

## Что лучше не делать

- Не копировать `preview.html` в Tilda целиком.
- Не оставлять локальные пути на файлы из репозитория.
- Не рассчитывать на `contact.js` как на продовую форму.
- Не вставлять CSS и JS без тегов `<style>` и `<script>`.
- Не пытаться сначала собрать всю страницу, а потом искать, какой именно блок все сломал.

## Блог и статьи

Папка `10-articles` содержит шаблоны, а не полностью автоматизированный блог для Tilda.

Есть два реалистичных сценария.

### Вариант A. Статические страницы в Tilda

Подходит, если статей немного.

1. Создайте страницу `/articles/`.
2. Вставьте в нее `10-articles/list.css` и `10-articles/list.html` через T123.
3. Для каждой статьи создайте отдельную страницу в Tilda.
4. Вставьте в нее `10-articles/article.css` и `10-articles/article.html`.
5. Обновите все ссылки, изображения, даты, SEO-поля и JSON-LD вручную.

### Вариант B. Feeds Tilda + ваши стили

Подходит, если статьи будут публиковаться регулярно.

1. Создайте Feed в Tilda.
2. Используйте Tilda для хранения записей и URL.
3. Наши шаблоны используйте только как визуальную основу.
4. Потребуется отдельная адаптация разметки под поля Tilda Feed.

Если нужен просто рабочий запуск, вариант A быстрее и надежнее.

## Диагностика типовых проблем

| Симптом | Причина | Что делать |
|---|---|---|
| CSS виден как текст | CSS вставлен без `<style>` или не в T123 | Вставить код в `T123` и обернуть в `<style>` |
| Картинка не грузится | Остался локальный путь из репозитория | Загрузить файл в Tilda и заменить URL |
| PDF не открывается | Ссылка ведет на локальный файл | Загрузить PDF и заменить `href`/`data-preview` |
| Форма "работает", но заявки не приходят | `contact.js` демонстрационный | Подключить штатную форму Tilda или реальный endpoint |
| Анимации не работают | Не подключен `_global/global.head.html` | Вставить содержимое `_global/global.head.html` в `HTML-код для вставки внутрь HEAD` |
| Цвета и типографика отличаются | Не подключен `_global/head.html` | Вставить код в HEAD сайта |

## Рекомендованный способ работы

Самый устойчивый сценарий такой:

1. Сначала подгоняете внешний вид в локальном preview.
2. Потом переносите секции в Tilda по одной.
3. На этапе переноса сразу меняете все локальные `src` и `href`.
4. Форму, документы и policy-page собираете уже как сущности Tilda, а не как локальные файлы из репозитория.

Если нужна именно беспроблемная продовая интеграция, этот репозиторий стоит воспринимать как набор исходников секций для ручной сборки в Tilda, а не как готовый Tilda-export.
